# Bug: 训练框架结构化输出失败时缺少定位信息

- **发现日期**: 2026-08-11
- **修复日期**: 2026-08-11
- **严重程度**: major
- **影响范围**: 训练方案草稿的训练框架阶段

## 现象

训练页只显示“AI 返回内容无法解析为可执行结构”，无法判断是 JSON 截断、字段缺失还是本地 Schema 校验失败。

## 根因

训练框架请求的输出上限为 1300 tokens，但框架合同要求完整的 `periodization`、`load_progression`、能力差距、风险和解释；同时 Runner 只把失败统一映射为 `schema_invalid`，没有记录脱敏校验原因。

## 修复方案

- 将 `build-training-framework` 的输出上限提高到 2200 tokens。
- 记录阶段、输出模型、脱敏 Schema 路径/原因、JSON 字节数；不记录 Prompt、Provider 正文或用户事实。
- 为框架和近期课表阶段增加失败原因日志。
- 修复近期课表阶段上下文漏传 `training_load_envelope` 的接线错误，复用框架阶段使用的同一确定性负荷边界。
- 按确认的边界，将近期课表中的标准星期名称（中文/英文及数字字符串）确定性规范化为合同所需的 `0–6`；其它非法值仍拒绝。
- 按确认的边界，接受严格 `YYYY-MM-DD` 的课程日期并转换为 `0–6`；当非休息课已有 `type` 和自然语言 `intensity` 但缺少 `intensity_intent` 时，只补齐体感型强度意图，不推造配速或心率。
- 修复训练框架仅校验 `periodization` 数组非空、却允许空阶段对象的问题；每阶段现在必须有名称、正周数和目的，避免后续周期渲染空白卡片。

## 验证

- Runner 回归测试覆盖 2200 token 合同与 Schema 原因日志。
- 8080 重启后真实重试确认：训练框架已成功解析；第二阶段此前因漏传 `training_load_envelope` 失败，修复后需继续验证完整草稿链路。
- 修复后真实重试确认 `training_load_envelope` 已传入且近期课表 Provider 请求成功返回；当前仍有一次可复现的模型合同问题：某堂非休息课缺少 `intensity_intent`，因此按既定严格 Schema 拒绝。是否允许确定性补齐该字段属于待确认的产品边界，当前未放宽校验。
- 用户确认允许星期名称规范化；新增回归覆盖 `星期六` → `5`。
- 用户确认允许 ISO 日期转换和保守强度意图补齐；回归覆盖 `2026-08-08` → `5`，以及长距离课补齐 Z2/体感意图。
- 当前草稿的后续周期空白已定位为 Provider 返回的空阶段对象；修复后需重新生成草稿验证。
- 当前周/下一周课程此前只投影了模型的课程骨架，未把同一份确定性 `training_prescription` 投影到草稿预览，因此页面看起来像固定的距离和体感模板。现在投影层复用个人配速校准与当天安全调整，非休息课可展开查看配速、分段、完成标准和调整边界；无可靠配速事实时仍明确降级为体感。
- 真实重试显示 Provider 会把 Runner 内嵌的空数组示例当作可接受框架输出，连续遗漏必需的 `load_progression`；示例已改为最小非空阶段与负荷项，仍由 Schema 拒绝任何实际空列表。
- 增加仅本地启用的 `NEURUN_AI_DEBUG_PROMPTS=true`：草稿两次 AI 调用会按同一 `generation_id` 打印四步执行轨迹、调用序号、完整 system prompt 和用户事实载荷，供短期定位；默认关闭且严禁线上启用。
- 草稿预览的近期课程不再沿用正式七日周视图的微型卡片字号；草稿专用响应式卡片保留可读距离、强度和课程详情入口。
