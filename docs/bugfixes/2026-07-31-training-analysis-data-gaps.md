# Bug: 日报缺少完整训练史、间歇结构和爬升负荷语义

- **发现日期**: 2026-07-31
- **修复日期**: 2026-07-31
- **严重程度**: major
- **影响范围**: 活动同步、日报生成、AI 教练历史上下文、训练负荷与 MCP 活动详情

## 现象

用户未逐日生成日报时，AI 教练的近期训练史会跳过已有原始活动；活动分段详情没有进入主同步链，间歇跑只能依赖名称猜测；Provider 已返回的累计爬升没有持久化，坡跑和山地训练无法影响后续建议。日报 ACWR 同时读取了错误负荷字段，并把 28 天负荷按活动条数平均。

## 根因

- `coach.py` 从历史日报文件构建训练史，把解释快照误当成完整训练事实。
- `sync_all_activity_details()` 没有接入主同步流程，重复写入还会复制分段。
- `ActivityData.elevation_gain` 没有写入 `activities` 扩展列，缺失值又与真实零值混用。
- `MemoryWriter._calc_training_load()` 读取 `activity_training_load`，但当前查询返回 `training_load`；慢性负荷的时间单位也与 7 天急性负荷不一致。
- 系统没有独立、可解释、版本化的训练内容分析领域层。

## 修复方案

- 新增双轴 `TrainingSessionAnalyzer`，分别识别训练主类型和地形属性，并保存置信度、证据、数据质量、个人基线快照和算法版本。
- 个人基线只使用活动发生前 28 天数据，样本不足时最多扩展到 42 天；当前恢复状态只影响刺激解释和后续建议，不改变既有分段或地形事实。
- 主同步尽力补齐 Provider 活动详情，归一化常见 laps/splits，并通过先删后写保证幂等；累计爬升、最大心率、卡路里和 Provider 一并持久化。
- 教练与 MCP 的近期上下文直接读取 SQLite 原始活动；日报保存当时分析快照并把爬升专项约束传给后续建议。
- ACWR 使用近 7 天累计负荷与近 28 天周均负荷，兼容数据库实际字段名；缺失爬升使用 `null`。

## 验证

- 自动化测试覆盖有氧、节奏、间歇、坡地、越野、山地、复合类型、不同个人基线和数据不足场景。
- 验证无历史日报时仍从 SQLite 返回训练日、距离、时长和负荷。
- 验证详情重同步不会复制分段，Provider 同步可保存常见嵌套 laps。
- 验证爬升约束进入日报后续建议，平台原始训练负荷不被覆盖。
