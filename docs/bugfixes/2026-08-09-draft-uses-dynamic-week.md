# Bug: 草稿基线使用动态周数据并可能复制上一周负荷

- **发现日期**: 2026-08-09
- **修复日期**: 2026-08-09
- **严重程度**: major
- **影响范围**: 训练方案草稿的周量基线、阶段切入判断和首周课程生成

## 现象

训练草稿会把当前未结束周或最近 7 天滚动跑量作为起始基线，动态周突然增加时可能抬高草稿负荷；即使使用上一周数据，也可能直接复制上一周跑量，没有先判断是否可以缩短适应周期或提前进入更高阶段。

## 根因

Web setup 同时提供了最近 7 天跑量和 28 天窗口，`TrainingLoadEnvelope` 与周量建议优先读取最近 7 天字段。Prompt 也没有把“上一周是参考事实而非模板”以及“先做 entry review 再决定阶段推进”设为明确约束。

## 修复方案

草稿基线窗口固定为上一完整自然周（周一至周日），并在 FactPack 中记录窗口类型和起止日期。动态当前周数据不进入草稿周量/负荷基线，只用于执行反馈、恢复和后续复盘。Prompt 要求同次 `entry_review` 先判断当前能力、连续性、有氧基础、近期表现、恢复、安全和目标剩余时间是否支持缩短周期/提前阶段；只有证据充分才允许小幅拔高，不能原样复制上一周课表。

## 验证

回归测试验证当前周高跑量不会抬高草稿基线，上一完整自然周跑量进入 FactPack；验证非法执行结构仍由 Validator 拒绝，并运行全量 `pytest` 和 8080 健康检查。
