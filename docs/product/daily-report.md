# 产品方案 — 报告中心、日报与数据完整性

> 版本: v1.3 · 日期: 2026-08-14
> 状态: 报告中心边界、日报/周复盘与训练调整深链已实现；Coros L2 与跨入口六项运动事实已有本地回放证据。`TrainingDayFact`、确定性单日分析、周复盘前置清单、质量课总结与三消费者投影的统一强合同已确认；空白布局修复、从存量 `summary_version` 到 `fact_version` 的工程收敛及线上 Provider/ECS 验收待完成
> 配套技术设计: [memory-system.md](../design/memory-system.md#日报生成前数据完整性门禁已实现)

## 1. 背景与问题

日报会把活动、睡眠、晨起指标和近期负荷聚合为训练与恢复判断。当前 Web 和 MCP 可以直接读取
本地 SQLite 生成日报，但“本地有一些数据”不等于“报告依赖的数据已经同步完整”。活动尚未同步、
健康指标只完成一部分或近期窗口覆盖不足时直接调用 AI，会把缺失误解为休息、低负荷或良好恢复，
生成看似完整但依据不足的结论。

## 2. 产品目标

报告中心是 neurun 的“观察—解释—决策建议”主线。训练模块负责把报告结论、目标和个体能力转成可确认、可执行的训练方案；报告不直接写入方案，训练也不重复实现报告的历史复盘。

- 生成日报前先证明数据覆盖状态，不以记录是否存在代替完整性判断。
- 核心事实不完整时不写日报、不调用 AI，并提供可执行的补齐动作。
- 非核心分析窗口不足时不猜测；用户可以明确选择受限版，缺失维度对应的结论必须省略。
- Web、CLI 和 MCP 使用同一套门禁，不因入口不同得到不同可信度的报告。
- 每份日报保存生成时的数据覆盖快照、数据截止时间和最终性，历史报告可以解释其依据。
- 日报只关联报告日期当时已经生效的训练方案和具体课次，不能用后来启用的方案反向评价历史训练。
- 同步、训练方案和日报共享同一份日期覆盖事实：同步补齐事实，训练方案据此更新能力与可比较状态，日报只解释当日事实和当时计划，不由三者互相静默写入。
- 日报在线教练只消费服务端已经固化的结构化事实并执行一次解释，不开放通用聊天，也不让模型在日报生成过程中自行调用查询或写入工具。
- 日报、周复盘和方案草稿统一消费确定性的 `TrainingDayFact` 与可定位的结构化 evidence，避免同一日期被不同入口重复计算出不同事实。
- 日报、周复盘和方案草稿统一复用确定性的单日分析；只有用户显式生成日报时才允许调用一次
  `review-daily-training` 做语义解释，周复盘不得为了补齐七天日报而串行发起 N 次单日 AI 请求。
  AI 失败、超时或容量不足时仍交付事实与确定性章节，不阻断三类入口。

成功指标：

- 日报、周复盘在无任务、无归档或折叠状态下的无内容占位模块数为 `0`；
- 每次周复盘对范围内已发生日期的前置清单覆盖率为 `100%`，每个日期都有可追溯的
  `ready` / `degraded` / `failed` 状态，而不是被静默跳过；
- 单次周复盘在线 AI 请求数不超过 `1`，逐日 AI 请求数为 `0`；
- Garmin、Coros 进入统一事实层后，对相同结构夹具的质量课分类和六项运动事实一致性测试通过率为 `100%`。

## 3. 范围与边界

### 3.0 报告中心职责与二级导航（已实现）

主导航名称为“报告”，而不是“日报”。报告中心是用户理解自身状态和决定下一步的主入口，按时间尺度组织 Daily Report 和 Weekly Review，
二者不得在同一长页面平铺。进入 `/reports` 默认停在 **日报**，用户通过稳定二级导航切换
**日报 / 周复盘**：

- **日报**解释某一天发生的活动、恢复、数据质量和当日计划匹配；
- **周复盘**解释一个自然周的实际活动、表现、恢复、能力变化和目标进程；有生效方案时才附加计划执行与 Progression Decision；在阶段边界上可提出下一阶段建议；
- **训练调整**属于训练方案的版本与提案历史，不作为报告类别重复展示；
- 报告可以深链到训练页的“调整今天训练”“查看调整差异”或“确认方案级调整”，但不得在报告页静默修改 Training Scheme；
- 报告中心不负责同步：数据缺口只引导到同步页，完成同步后回到原报告时间范围重新检查。

周报只能由用户显式生成或刷新；浏览、筛选或导出周报不得产生新的 Progression Decision、Adjustment Proposal 或 Training Scheme Version。周报的“建议加快”“建议减量”“调整本周”或“建议进入下一阶段”只能形成带报告/周 ID 的训练深链；训练页查看差异并经用户确认后，才可能影响未来安排。

已归档且包含 `accelerate`、`deload` 或 `replan` 建议的周复盘提供“在训练中生成调整提案”动作。该动作调用训练域的报告引用接口，使用 `report_id`、`week_id`、方案 ID/版本和事实截止时间校验当前方案，生成 `status=pending` 的方案级提案；默认从下一自然周开始生效。用户仍需在训练页查看差异并确认，报告页和该接口都不能直接改变方案。

周复盘是报告中心的独立用户能力，不以 Training Goal、草稿或已生效 Training Scheme 作为生成前置条件。系统始终先生成基于真实活动、恢复、能力趋势与数据完整度的“基础周复盘”；指定自然周存在生效方案时，再叠加计划课次对比、方案版本和 Progression Decision。没有方案时不展示完成率、偏离判定或方案推进结论，但必须允许生成、归档和查看复盘；可提供“制定训练方案”次要入口，不得将其表达为补齐报告的必做任务。

“基础周复盘”不能退化为次数、总里程和一句通用建议。即使没有训练方案，正式周复盘也必须回答四个问题：本周具体发生了什么、相对最近完整自然周发生了什么变化、恢复与负荷有哪些风险或未知、下周最值得执行的动作是什么。至少展示运动天数与跑步天数、时长、最长单次、运动/训练类型结构、近四个数据完整周的跑量与频次对比、数据覆盖、可用恢复事实、风险标记和 2–3 条可执行建议。缺少恢复、训练识别或足够历史周时明确说明“该维度未知”，不得用空卡或泛化文案假装已分析。

日报生成与周复盘、方案调整等在线 AI 工作共享同一进程容量。同一用户已有任一生成任务时，重复提交立即提示“已有 AI 任务进行中”；其他用户仍可使用剩余容量。全局执行槽位暂满时只允许短暂等待，等待过程不创建推理线程；超过总接纳量或等待时限后提示稍后重试。未执行的请求不写入日报、周复盘、提案或训练方案，用户重试前仍可查看既有内容。

已接纳的 AI 生成任务不得因用户刷新或离开页面变成不可解释的占位。报告页重新进入时必须恢复当前用户的任务状态：至少区分“等待执行、正在生成、已完成、失败”，显示已等待/执行时间，并说明页面可以安全刷新。模型调用没有可靠分步进度时不得伪造百分比。周中进度检查属于非持久化结果，后台完成后需要在短期任务状态中保留该用户可读取的结果，使刷新后的页面无需再次调用 AI 即可恢复本次结论；正式周复盘仍以报告归档为真相源。

周复盘的活动、趋势、恢复风险、计划执行和推进候选先由本地确定性逻辑完整计算，在线 AI 只负责一次最终解释，不得把计划执行和恢复再次拆成串行模型请求。周复盘在线解释自开始执行起最多等待 45 秒；上游超时、缓慢持续返回或输出无效时立即使用完整的确定性复盘，释放当前账户的生成占位并允许后续任务。超时不能留下长期 `running` 状态，也不能阻塞同一账户的方案调整。

报告中心的隐藏状态必须真正退出布局，而不是只去掉文字。二级 Tab 下方的任务状态条只在
`queued`、`running`、需要用户处理的 `failed` 或刚完成且仍有必要反馈时出现；其余状态占用高度为
`0`。折叠的周复盘详情只显示摘要行，未展开的正文、分区和
列表全部退出布局。日报或周复盘没有归档时，各自只显示一个包含原因和可执行动作的紧凑空状态；归档列表
容器、分页、空的详情分区和没有内容的标题不得渲染。单个事实维度不可用时按本节既有缺口规则隐藏或合并，
不能生成无文字、只有圆角背景或只有固定间距的空白模块。

日报页只承担“选定日期是否已有报告、如何查看/生成、最近日报归档”三件事。日期是日报页唯一的范围控件；
仅在用户准备生成、日报缺失或数据异常时展开 data readiness，已有日报只显示简短完整性状态。日报列表只保留日期、
训练摘要与报告状态，不在列表并列睡眠、恢复等详情指标。日报与已完成周复盘的归档列表均采用分页：每页展示有限且稳定数量的项目，分页条显示当前页、总页数与总数，并提供上一页/下一页操作；翻页只改变对应归档列表，不能改变当前日报日期、周复盘日期、二级 Tab 或触发报告生成。

日报与周复盘都使用相同的“范围摘要 + 明确修改入口”日期控件：摘要显示完整日期与星期（周复盘显示自然周范围），
可见日期字段负责精确选择，前后日期和昨天 / 今天、上一周 / 本周提供轻量快捷操作。日报摘要同时说明是否已有报告和
完整性状态；日期不得晚于用户本地今天。日期控件不能退化为没有样式或上下文的裸原生输入框。

周复盘页只承担自然周的进度与归档：周中显示“本周进度/周中检查”，不得生成正式推进结论；自然周结束后或用户
显式生成时才形成周复盘及 Progression Decision。待确认调整和历史方案版本只在训练页查看；没有记录时不得
在日报首页保留大面积空状态。

### 3.1 本期范围

- 指定日期日报生成前的数据就绪检查。
- 活动、睡眠、恢复指标、近 7 天趋势和近 28 天负荷的分维度覆盖状态。
- Web 生成前预检、服务端二次校验、同步引导和受限版确认。
- CLI、MCP 与 Web 的统一生成门禁和结构化错误。
- 日报 Front Matter 中的数据质量快照。
- 日报正文与 AI 洞察引用训练域只读运动员能力画像（`athlete_context`），作为当日/近期负荷相对个人可持续容量的解释背景；不做趋势图、不新增页面。

### 3.1.1 能力与近期负荷背景引用（已确认）

日报生成时从训练域读取一次只读能力画像（与方案草稿同口径的
`TrainingService.capacity_profile(D)`，即 Web 已暴露的 `GET /api/training/capacity`），
投影为 `athlete_context` 写入 Front Matter：

- 引用内容：可持续周跑量参考、长距离参考、近期参考配速、历史已证能力与中断背景、
  负荷边界、同步覆盖与置信度、`facts_cutoff`。
- 使用方式：日报正文（负荷状态章节）展示一行紧凑背景；`review-daily-training` 的
  `daily_facts` 注入同一份背景，AI 在单次调用内解释当日负荷/本周跑量相对能力的相对位置。
- 门禁：`training_load` 被省略的受限版不得输出背景（能力与负荷解读依赖负荷结论）；
  训练域读取失败或没有足够活动事实时标记 `status=unavailable` / 低置信度，不得编造能力数值。
- 快照语义：报告固化生成时点的画像与事实截止时间，之后重算不反写历史日报；
  重新生成历史日期仍按 `capacity_profile(D)` 口径读取，不引用 `D` 之后的活动。
- 边界：日报只把能力画像作为只读解释背景，不写回训练域、不参与方案计算；
  能力画像的计算仍由训练域负责，报告域不重复实现。

### 3.2 非本期范围

- 同步完成后自动生成日报；同步与生成仍是两个独立旅程。
- 用推测值填补 Provider 没有返回的睡眠、心率、HRV 或训练负荷。
- 要求所有 Provider 提供完全相同的指标；完整性按已绑定平台和已授权能力判断。
- 把“今天截至当前时刻的数据”描述为全天最终数据。
- Web 通用聊天、聊天历史、流式对话接口或由聊天触发的训练写入。

### 3.3 共享单日摘要用户旅程

日报、周复盘和训练方案草稿共用一个确定性的 `TrainingDayFact` 事实层。事实以用户本地日期为锚点，由统一构造器从 `SessionSummaryFacts`、健康数据、训练内容识别、同步覆盖和当时的方案版本计算；它不要求历史日报已生成，也不由 AI 自由补写。各入口不得维护第二套单日解析。

每个 `TrainingDayFact` 必须同时具备：

- `schema_version`：表示 `TrainingDayFact` 的字段与语义合同；
- `fact_version`：对 schema、计算规则版本、本地日期、事实截止时间、引用的
  session/健康/覆盖/方案版本和业务内容做规范化哈希后的事实身份；
- `source_fact_versions`：该日引用的每条 `SessionSummaryFacts.fact_version` 及健康、
  覆盖和方案快照引用；
- 事实字段的 `ValueOrGap` 和结构化 evidence，以及 `data_as_of`、`finality`、
  事实状态和当时方案上下文。

`schema_version`、`fact_version` 和上游 `detail_hash` 不是同一概念。新数据不再把
`summary_version` 作为泛化版本名写入；它只是存量 `TrainingDayFact.fact_version`
的读取别名。重新同步、事实重算、schema 或规则升级产生新 `fact_version`
时，历史报告保留生成时锁定的版本，不能后台静默改写。

`TrainingDayFact` 的最小可追溯内容为：

- 日期范围、`data_as_of`、`schema_version`、`fact_version` 和 `finality`；
- 活动、睡眠、恢复和历史窗口各自的覆盖状态（`complete`、`unsupported`、`missing`、`syncing`、`failed`、`insufficient_history`）；
- 实际活动集合（可为空，但活动覆盖完成时才可解释为确认休息），每条活动的来源 ID、开始时间、距离/时长、关键指标和训练识别结果；
- 当日计划上下文：有效方案版本与课次，或 `no_effective_plan`、`draft_available`、`scheduled_plan`；不适用状态不能被转换成未执行；
- `evidence` 和 `gaps`：证据必须定位到结构化事实或来源记录，缺口必须说明受影响的维度和章节。

### 3.3.1 运动摘要事实（Session Summary Facts）

每条已同步活动可以在事实层生成一个版本化的 `SessionSummaryFacts`，作为
`TrainingDayFact` 中活动指标、训练内容证据以及日报/周复盘解释的确定性来源。它是内部事实，
不新增摘要页面、设置项或用户确认步骤；用户仍通过现有报告和训练页面查看渐进披露的证据。

- 摘要只从已入库的 Provider 活动、分段和可用详情指标确定性归一化与聚合，不读取日报正文，
  也不让 AI 直接读取原始 `detail_json` 或 1Hz 明细数组。
- 每条摘要标记 `granularity`：`L0` 仅有经验证的活动汇总量，`L1` 必须具备通过
  数量门禁的有序分段，`L2` 只在
  1Hz 原始点已经完成 Provider 字段解析、单位归一化、无效点过滤和确定性聚合后提供精确强度与
  坡度分布。`detail_json` 中存在 `frequencyList` 或其他原始数组本身不构成 L2；Coros 原始 Hz
  已保存但未解析期间必须停留在 `L1`/`L0` 并显式记录 `hz_unparsed`。缺少上层数据时自动降级，
  不得把低粒度结果展示成精确测量。
- 心率不可用时可以用配速带作为强度依据，但必须在证据和报告中标记
  `intensity.basis=pace`；系统不得把代理值写成心率结论或补造缺失心率。
- 摘要的 `schema_version`、`detail_hash`、`fact_version`、规则版本、来源活动 ID、
  观测时间、粒度、缺口和代理声明都属于可追溯合同。重新同步、schema 或规则变化会产生新 `fact_version`；已归档报告继续使用
  生成时引用的版本，不能后台静默改写。
- 摘要计算失败不应让已同步活动丢失；报告和训练事实必须标记受影响的摘要维度为未知，并省略
  依赖该维度的结论，不能用零值或泛化文案替代。
- 每条跑步摘要必须对以下六项分别给出规范值或字段级 `gap`：活动距离、平均配速、有序分段
  （只有公里语义经门禁确认后才称“每公里分段”）、心率、步频、步幅。`gap.reason` 至少区分
  `not_provided`、`not_authorized`、`not_mapped`、`unit_unverified`、`hz_unparsed`、
  `quantity_unreliable` 和 `projection_omitted`；可用字段不得在下游投影时静默丢弃，缺失字段不得填零。

### 3.3.2 训练深度分析（分段粒度，已确认）

日报“训练细节分析”从 evidence 列表升级为确定性深度分析（统一 `session-summary` schema），全部本地计算、
数值可核对，不依赖 AI 编造：

1. **整体水平**：距离/用时（无暂停 = moving vs elapsed 对比）、平均配速（折合全马预测）、最快配速、
   爬升/下降/海拔范围、平均/最大步频、热量、训练效果与强度分钟。
2. **强度分布**（分段粒度，标注样本数）：配速带占比、配速分位数 P5/P25/P50/P75/P95、心率带占比、
   课型判定（间歇/节奏/变速/复合）。
3. **配速节奏**（逐分段）：逐段配速/心率、前后半程秒差与正负分段、最快/最慢段、配速 CV、
   节奏轮廓、work/recovery 复合结构。

规则：

- 只对跑步活动且存在分段数据时产出；`L0`（无分段）只展示整体水平并明确“强度分布/配速节奏不可得”，
  不得把分段粒度描述成秒级精度；非跑步活动不做配速/强度分析（只保留总量与原始训练效果）。
- 训练效果：Provider 原始 TE 优先；缺失时用个人阈值（心率或配速）做强度时间加权估算，**必须标记**
  “估算”并说明估算方法与依据（心率/配速代理）；阈值也不可用时显示“不可得”，不伪造数值。
- **个人阈值只来自档案，不猜测**：优先用户确认的阈值（心率/配速），其次由档案最大心率推导
  （阈值心率 ≈ 88% 心率储备，静息心率参与 Karvonen 计算）；档案两者都没有时，不得用近期训练
  平均心率/配速分位充当阈值。训练内容识别的强度证据在缺少个人阈值时输出
  “缺少个人阈值心率/配速，强度评估不可用”，不给出“为个人阈值心率的 X%”精确数字。
- 版本化：单一 `session-summary` schema，维度演进直接并入；历史报告保留引用版本，不后台重算。
- AI 只引用结构化事实做定性解释（配速水平、训练含义），不重新计算数值。

### 3.3.3 训练结构识别（加权确定性判定，已确认）

日报“训练结构”从单一标签升级为**加权确定性判定**，不使用 AI 判断结构：
（数据源为 Garmin `/splits` 官方分段 `lapDTOs`——同步时仅对跑步活动拉取并入库，
可信分段；无 `lapDTOs` 的存量活动由数量门禁兜底，只输出强度模式）

- **六类**：变速（fartlek）/ 间歇（interval）/ 节奏（tempo）/ 有氧（aerobic）/ 混合（mixed）/ 未知（unknown）
- **加权证据**：配速 0.40（主）、心率 0.35（主）、步频 0.15（辅）、步幅 0.10（辅）；
  四维度各自独立降级（秒级序列缺失 → 段级 → summary），缺失只降低置信度与成分精度，不断言不一致。
- **结构判定**：快段识别（配速快 ≥12% + 心率抬升 ≥8% 双证据，步频/步幅响应修正置信）→
  交替组数 ≥2 为变速/间歇（快段规律且强度 ≥ 阈值带 → 间歇，否则变速）→ 无交替按强度带分节奏（Z3）/有氧（Z2）。
- **数据门禁**：分段距离合计 vs summary 距离比值 ∉ [0.85, 1.15] 时标记量特征不可信，
  只输出强度模式（配速/心率/步频/步幅序列特征），不输出段距离/时长结论。
- **独立特征**：疲劳复合信号（心率漂移 + 步幅后半程下降 + 配速维持）与效率特征（步频一致性）
  作为展示与周报趋势，不参与六类结构判定以外的结论。
- **置信度**：`confidence = Σ(采用证据权重)`，标注缺失证据；主证据不足（无配速且无心率）时
  判定降级为 `unknown` 并说明原因，不猜测。

验收标准补充：

50. 跑步活动存在分段序列时，日报展示六类结构判定与加权置信度；快慢交替 ≥2 组判定变速/间歇，
    无交替按强度带分节奏/有氧，主证据不足时降级 `unknown` 并说明，不用 AI 判断结构。
51. 步频/步幅参与判定但权重低于配速/心率：缺失只降置信与成分精度，不改变已由配速+心率确定的结构结论；
    结构判定与效率/疲劳特征分开展示。
52. 分段距离合计 vs summary 比值超 [0.85, 1.15] 时标记量特征不可信：只输出强度模式，不输出段距离/时长结论。
57. 存量活动（旧 schema summary 无 `segment_sequence`/`quantity_gate`）重新生成日报时，从 `activity_splits` 重建分段特征序列并重算量特征门禁后做确定性结构判定；如单次跑步融合分段变速（1 组快慢交替）识别为"混合"，Garmin splitSummaries ×2 距离异常标记为仅强度模式，不误判为间歇或 unknown。
58. 运动概要含间歇/变速/混合课型且 `work_recovery_groups` 非空时，逐组列出每组快/慢配速与心率（按组序号升序、全部组）；`session_summary.effect` 可用时给出训练效果解释（TE 值 + 强度含义），估算值带"估算，依据心率/配速"标注，不可得时如实说明。
53. 训练日日报的"教练观察"至少包含运动概要、强度分布解释与分析、恢复分析、近 7 天负荷与恢复分析四块内容，且为连贯自然语言，不输出纯数值罗列。
54. 强度分布解释引用配速带/心率带占比或分位数，并在可用时包含平均步频与步幅；无心率时标注 `basis=pace`，无分段、步频或步幅时明确缺失，不补造。
55. 恢复分析把睡眠、HRV/静息心率、身体电量、恢复评分合并为一段连贯表达；近 7 天负荷与恢复块输出 ACWR（急性/慢性对比）与近一周睡眠/HRV 趋势；同一事实在两块及各观察之间只出现一次，不与结论、建议重复强调。
56. 无负荷数据或 7 天健康窗口不足时，"近 7 天负荷与恢复"块按可用证据降级：缺 28 天基准只报急性负荷并说明无法判断相对位置；无任何负荷或趋势证据时不输出该块，不编造 ACWR 或趋势结论。

`evidence` 不是一段仅供展示的文案。每项至少具有 `kind`（事实、覆盖或推断）、`source`、`field`、`observed_at`/`data_as_of`、`value`（可空）和 `confidence`（不适用时可空）；页面、Markdown、导出和 MCP 都从这些字段生成可读解释。任何缺口、不可比较或低置信度结论必须保留对应 evidence/gaps，不能用零值、空字符串或泛化建议代替。

### 3.3.4 教练观察内容规范（已确认）

日报"教练观察"（`CoachInsight.observations`，AI 与本地降级同形态）是报告中心的自然语言解读层，内容固定由三块组成，全部用连贯的自然语言成句，同一事实只出现一次，不与结论、建议或警告重复强调。

**页面呈现**：教练观察不再单独占区块，四块话语与结论一起渲染在日报顶部"今日结论"区（结论一句话 + 四块观察段落），其下再展示计划执行、训练事实、恢复与负荷数值，避免顶部信息重复强调。

1. **运动概要**：当天练了什么——距离/用时、平均配速、课型结构（引用结构判定的 `label`/交替组数/每组快慢配速明细）与整体水平；只陈述事实，不展开强度细节。课型为间歇/变速/混合且 `work_recovery_groups` 非空时，**必须按组序号逐组列出每组快/慢配速与心率**（如"间歇结构（4 组快慢交替）：第1组快 3'44"/km(hr147) → 慢 5'04"/km(hr139)；第2组…第4组…"）。同时引用 `session-summary.effect` 给出**训练效果解释**（有氧/无氧 TE 值 + 一句话强度含义，如"训练效果有氧 4.4，高强度刺激对体能提升作用明显"）；`estimated=true` 必须标注"估算，依据心率/配速"，TE 不可得时如实写"训练效果不可得"，不编造。
2. **强度分布的解释与分析**：引用 `session-summary` 的 `intensity`（配速带/心率带占比、`basis`）、`pace_profile`（分位数/CV/前后半程）与 `structure`（平均步频、步幅）解释分布落在什么强度、节奏与效率如何，例如"配速以 3'40"–4'20" 为主、心率 67% 时间在 130–145 区间、平均步频 184 spm、步幅 1.1m"。缺失维度（无心率 → `basis=pace`、无分段、无步频/步幅）必须如实说明，不得补造。
3. **恢复分析**：当日恢复状态——睡眠、HRV/静息心率、身体电量与恢复评分合并为一段连贯表达，说明今天恢复是否支持训练，例如"昨夜睡眠 6.3h 是主要限制，但身体电量与恢复评分支持正常训练"。
4. **近 7 天负荷与恢复分析**：趋势维度，不与当日恢复重复——引用 ACWR（7 天急性负荷 vs 28 天慢性基准）与近一周睡眠/HRV 等恢复指标方向，说明近期负荷与恢复的相对位置和走向，例如"ACWR 1.15 处于最优区间；但睡眠近 3 天走低（7.5h → 6.2h）、HRV 也在回落，疲劳在累积"。

规则：不输出只有数值的罗列，也不输出只有结论没有依据的断言；四块各自成段、按序输出；同一事实在四块之间只出现一次，不与 `conclusion`/`warnings`/`recommendations` 重复强调；低置信结构判定不得表述为确定结论。`session-summary` 缺配速/心率主证据时按确定性判定降级 `unknown`，观察如实说明原因。

事实写入或读取完成后，系统必须先生成确定性的 `TrainingDayAnalysis`。用户显式生成某日日报时，
可在该事实之上调用一次 `review-daily-training` 生成语义解释；旧的
`summarize-training-day` 名称只保留兼容读取，不再代表另一条 AI 调用。该调用只解释已固化事实，
输出标题、训练内容解释、风险/不确定性和下一步动作等自然语言，不查询新数据、不改变事实、不补齐缺口、
不写入方案。调用未执行、超时、容量拒绝、返回非法结构或 Provider 不可用时，记录
`semantic_status=unavailable` 及脱敏原因，仍交付确定性事实和本地可计算章节；AI 语义解释不可用不
阻断日报、周复盘或草稿读取/生成。训练方案候选自身若因其独立 AI 合同失败，仍按训练产品文档的草稿
失败边界处理，不能把事实层失败与方案候选失败混为一谈。

### 3.3.5 周复盘前置依赖流水线（已确认）

用户显式生成或刷新周复盘后，系统在一次周任务内按固定顺序完成以下前置步骤，再进入周级综合：

1. 锁定本地自然周范围与 `data_as_of`。已结束周包含周一至周日；当前周只包含截止时刻以前的日期，
   未来日期不创建休息、零负荷或缺口事实。
2. 对范围内每天逐日确保 `CanonicalActivityDetail -> SessionSummaryFacts -> TrainingDayFact`
   已按当前 schema、规则版本和输入指纹生成。版本一致时直接复用；来源事实变化时只重建受影响的日。
3. 从每个 `TrainingDayFact` 生成或复用同版本的确定性 `TrainingDayAnalysis`，统一完成当日运动概要、
   结构识别、强度/节奏、恢复与负荷、计划参考、质量课候选和 gaps 分析。该步骤不调用在线 AI，也不创建
   用户可见的日报 Markdown、图片或日报归档。
4. 将每天的 `fact_version`、`analysis_version`、覆盖状态、事实截止时间、质量课引用与 gaps 固化为
   `WeeklyPrerequisiteManifest`。只有清单封口后才允许形成周聚合与发起一次周级在线解释。
5. 周级确定性结果和质量课总结先完整生成；在线 AI 最多调用一次，只解释已固化周事实。AI 不可用时仍
   归档确定性周复盘，不重复执行单日 AI，也不要求用户先手工生成七份日报。

`TrainingDayAnalysis` 是共享的确定性分析事实，不是自然语言日报。它至少包含：
`schema_version`、`analysis_version`、`day_fact_version`、`source_session_fact_versions`、
`status`（`ready` / `degraded` / `failed`）、活动分析、质量课候选、覆盖、`data_as_of`、
`evidence` 和 `gaps`。`analysis_version` 由 schema、分析规则和全部来源事实版本确定；计算时间或消费入口
变化不得改变它。日报、周复盘和方案草稿读取相同 `day_fact_version + analysis_version` 时，确定性
结论必须一致，只允许按消费范围投影或省略。它聚合当日零到多条既有
`Training Session Analysis`，不替代活动级分析，也不等同于 `Daily Report` 或 AI 自然语言。

单日活动覆盖为 `complete` 且活动为空时，前置分析可以标记“确认休息”；覆盖为 `missing`、
`syncing`、`failed` 或未知时，只能生成 `degraded` 分析并保留受影响结论的 gap。单日分析失败不自动把
整周伪装成失败：周复盘继续使用其他日期并明确列出缺失日、受影响章节和置信度；只有无法建立周范围、
用户身份或任何可追溯事实时才阻断写入。重复点击、刷新或任务重试必须按版本幂等复用已完成的前置结果，
不得产生重复日报、重复质量课或重复 AI 请求。

### 3.3.6 质量课提取与周总结（已确认）

质量课由 `TrainingDayAnalysis` 从统一 `SessionSummaryFacts` 确定性提取，不由 Provider 名称、活动标题
关键词或 AI 自由判断。满足以下全部条件的跑步活动进入 `QualitySessionFact`：

- 结构分类为 `interval`、`tempo` 或 `fartlek`；`mixed` 仅在包含已识别的
  `work_recovery_groups` 时进入，`aerobic`、`unknown`、恢复跑和确认休息不进入；
- 结构置信度不低于 `0.60`，且至少有配速或心率一个主证据；
- 分段数量门禁失败时可以保留“强度模式质量课”，但不得输出不可靠的分段距离、时长或每公里结论，
  并必须携带 `quantity_unreliable` gap。

每条 `QualitySessionFact` 至少包含日期、活动 ID/来源、结构类型与置信度、`fact_version`、可用的距离、
时长、平均配速、心率、步频、步幅、可靠分段数、快慢组、训练效果、粒度、evidence 和 gaps；任一指标都
遵循 `ValueOrGap`，不得以 `0` 或空字符串代替缺失。Garmin、Coros 及后续 Provider 使用同一规则和字段，
除 Adapter 外不得出现平台专属质量课分支。

周复盘的“质量课总结”先确定性输出质量课次数、类型分布、总时长/距离、每节课的结构与关键指标、可验证
训练效果，以及与相邻日恢复/负荷的证据关系；在线 AI 只能把这些事实组织为自然语言，不重分类、不重算
指标。满足门槛的质量课为零时，显示一行“本周未识别出满足证据门槛的质量课”；存在疑似高强度但证据不足
的活动时，同时说明未计入的 gap，不渲染空白卡片。一天多节质量课分别保留，周聚合按活动 ID 去重。

三个消费入口的时间范围和职责固定如下：

| 入口 | 读取范围 | 负责回答 | 明确不负责 |
|---|---|---|---|
| 日报 | 选定本地日期 `D` 的 `TrainingDayFact + TrainingDayAnalysis`；活动只取 `D`，趋势/恢复可引用截至 `D` 的有限窗口 | 当日发生了什么、数据是否完整、当日计划参考和下一步动作；显式生成时可附一次 AI 语义解释 | 不生成周进程决定，不确认/激活/改写训练方案 |
| 周复盘 | 一个本地 Natural Week（周一至周日）的全部单日事实与确定性分析，比较窗口只取活动覆盖完整的历史自然周 | 本周实际、质量课、相对变化、恢复与风险、下周建议；有生效方案时附加计划执行和候选决策 | 不逐日调用 AI，不创建日报归档，不把建议直接应用到方案；只能深链训练页查看差异并确认 |
| 方案草稿 | 草稿生成时点以前的必要事实窗口；首周基线优先使用上一完整自然周，未来日期属于拟议排期而非事实 | 当前能力与约束依据、建议进入阶段、未来方案候选 | 不激活候选、不修改历史报告；确认和版本生效由训练流程负责 |

三个入口不直接修剪原对象，而是从同一组 `TrainingDayFact.fact_version`
生成带版本的 `ConsumerProjection`。每个投影必须包含 `schema_version`、
`fact_version`、`consumer`、`window`、`source_fact_versions`、`included_fields`、
`omitted_fields`、`evidence` 和 `gaps`；`consumer` 只能是 `daily_report`、
`weekly_review` 或 `training_planning`。投影不得重算上游事实，也不得产生第二个业务版本。

- 日报读取该日期完整聚合摘要，可展示六项事实、分段结构和详细 evidence；不读取原始 Hz 点。
- 周复盘读取自然周内的 compact projection，保留六项中可用的周聚合与必要分段结构；逐点数组、
  重复 evidence 和与周判断无关的分位明细可以省略，但被省略的可用字段必须进入
  `omitted_fields` 并标记 `not_required_for_consumer`，不能伪装成源 gap。
- 方案草稿只保留上一完整自然周的聚合基线和最近两个已结束自然日的会话级 compact summary。
  最近两日中可用的距离、平均配速、可靠分段、心率、步频和步幅必须保留；不可用项必须携带
  字段级 gap。草稿不得接收原始 `detail_json`、原始 Hz 点、完整历史逐段列表或重复 evidence。
  更早历史可只保留周量、频次、最长单次、训练类型和数据质量聚合。

跨入口只传递日期/自然周、`ConsumerProjection.fact_version`、上游
`source_fact_versions`、事实截止时间和返回来源；不因跳转创建任务或写入其他领域。上述范围使用现有日报/周复盘日期控件、训练草稿既有目标和开始日期输入，不新增摘要设置、AI 开关、证据编辑器、单日摘要列表或第二个确认页面。

## 4. 核心原则

1. **覆盖证据优先于数据存在性**：没有活动可能是确认休息，也可能是尚未同步；只有逐日、逐维度
   同步完成证据才能区分。存在一条跑步记录也不能证明当天睡眠和恢复指标完整。
2. **能力感知**：Provider 不支持的指标标记为“不适用”，不算缺失；Provider 支持但未授权、同步中
   或同步失败必须如实表达。
3. **按结论所需数据门禁**：缺少活动覆盖时整份日报无法成立；缺少睡眠或历史窗口时，禁止输出恢复、
   趋势或 ACWR 等对应结论，不能用零值代替。
4. **生成时再次校验**：页面预检只用于交互，真正写入前必须由服务端重新检查，避免预检后数据状态变化。
5. **时间边界透明**：今天生成的日报是“截至最近一次成功同步”的暂态报告；历史日期在覆盖完成后才可
   标记为最终报告。
6. **报告日期即活动归属日期**：选择日期 `D` 生成的日报只汇总 `D` 当天活动，并在页面、AI 洞察、
   导出和机器可读输出中称为“当日训练”或明确的 `D` 日训练。不得把 `D` 日活动称为“昨日训练”；
   “昨夜睡眠”仍表示进入 `D` 日清晨前结束的睡眠周期。
7. **计划执行与目标进展可解释**：存在 `effective` 方案时，日报必须单独呈现当日计划与已记录活动、截至
   `D` 的自然周累计与周目标、当前阶段及目标日期。活动覆盖未知、草稿、未来排期或当日无生效课程时，必须
   明确“不适用/待同步”，不能推断为未执行。
8. **报告提出建议，训练负责落地**：日报只提出当天下一步；周复盘提出下一周建议；阶段复盘可以提出下一阶段
   建议。所有建议都只能深链训练页查看、生成和确认调整，不在报告页批准提案、改写课次或宣称赛事目标已经达成/失败。
   赛事结果或正式测试是目标达成判断的必要事实。
9. **单日事实统一生成、按范围复用**：`TrainingDayFact` 与 `TrainingDayAnalysis` 由共享确定性构造器
   定义统一口径；日报、周复盘和方案草稿只能在各自时间范围内聚合或省略事实，不能另算活动归属、
   训练结构、质量课、覆盖状态或证据。`review-daily-training` 的自然语言结果属于日报显式生成时的
   可选解释层，不是周复盘前置事实或生成门禁。

## 5. 就绪状态

日报预检返回一个总体状态，并保留每个数据维度的独立证据：

| 总体状态 | 含义 | 默认动作 |
|---|---|---|
| `ready` | 核心数据和报告将使用的分析维度均有可验证覆盖 | 允许生成日报并调用 AI |
| `limited` | 核心活动事实可信，但一个或多个辅助维度缺失或历史不足 | 不默认生成；允许用户明确选择受限版 |
| `blocked` | 报告日期活动覆盖未知、同步中、同步失败或身份/数据源不可用 | 禁止写日报和调用 AI，先同步或修复 |

每个维度使用 `complete`、`unsupported`、`missing`、`syncing`、`failed` 或
`insufficient_history` 表达状态。至少检查：

- **报告日活动**：必须能证明“有训练”或“已确认休息”，否则总体为 `blocked`。
- **报告日睡眠**：在 Provider 支持且已授权时检查完成状态；缺失时总体为 `limited`，不得给睡眠恢复结论。
- **报告日恢复指标**：RHR、HRV、压力或训练准备度按 Provider 能力检查；缺失时总体为 `limited`，
  不得输出综合恢复判断。
- **近 7 天趋势**：覆盖不足时不计算趋势，不把缺失日当零值。
- **近 28 天负荷**：活动覆盖不足时不计算慢性负荷或 ACWR；新用户可以生成受限版，但不得伪造负荷风险。

`unsupported` 不降低就绪状态；“支持但未授权”必须展示授权入口，不能伪装为不支持。

## 6. 用户流程与交互

1. 用户通过日期摘要、可见精确日期字段或快捷操作选择日报日期后，页面先显示数据检查结果，再决定主按钮状态。
2. `ready` 时主按钮为“生成日报”，并显示数据截止时间。
3. `limited` 时页面逐项列出缺失维度、会被省略的报告章节及补齐方法；主动作是“先补齐数据”，
   次动作是“生成受限版”。次动作必须由用户显式触发，不能沿用上次选择。
4. `blocked` 时不显示可用的生成按钮；根据原因提供“同步这一天”“同步近 28 天”“重新授权”或
   “查看同步失败”的直接动作。“前往同步”必须携带当前报告日期，进入同步页后自动填入单日同步
   日期、切换到对应月份并定位到单日同步区域；同步完成返回日报页时继续保留该日期。
5. 用户提交生成后，服务端再次检查。状态已变化时返回最新检查结果，不生成旧条件下的报告。
6. 受限版必须在列表、详情和导出图片中持续显示“数据不完整”，列出数据截止时间和省略项；不得只在
   生成前提示一次。日报详情的恢复/负荷模块在对应维度无数据时不得渲染空白占位块：单个模块直接隐藏，
   剩余卡片必须按实际可见数量重新均匀分列并连续排列，不得因 Provider 只返回部分恢复字段而留下固定
   列宽空位或孤立左对齐；整组无数据时隐藏整块区域，全部依据缺失时“数据依据”折叠区收拢为一行说明（如
   “查看数据依据：当日睡眠、恢复与负荷数据暂缺（受限版）”），避免出现只有“—”的空白卡片。
7. 今天的报告始终显示“截至 HH:mm”，后续同步到新数据时提示可重新生成；只有已结束的历史日期才能
   标记为“最终”。
8. 报告内所有训练日期文案使用报告日期作为锚点。切换、查看或导出历史日报时，不使用查看当天的
   “昨天/今天”相对称谓替代报告日期。
9. 报告日期 `D` 的计划联动必须先解析 `D` 当时生效的方案版本，再解析日期为 `D` 的具体训练课。
   若 `D` 早于首个方案生效时间、处于两个版本的空档或没有可解析课次，报告不进行执行评价。当天已有
   待确认草稿时显示“已有待确认方案草稿，仅供参考”；已有未来启用安排时显示正式开始日；完全没有方案时
   才显示“当日尚无生效计划”。三者均不得输出“未执行”“偏离计划”或完成率。后来创建、激活或调整的
   方案不能反向套用到 `D`。
10. 从同步页返回日报时，报告日期与同步事实截止时间必须一并保留；若本次同步补齐活动、健康或历史窗口，
    日报页重新检查 readiness 并提示“数据已更新，可重新生成”。同步本身不自动生成或覆盖日报。
11. `/reports` 的二级导航状态必须可由 `tab=daily|weekly` 表达。来自同步的链接固定进入
    `tab=daily` 并保留 `date=D`；来自训练的周复盘链接固定进入 `tab=weekly` 并保留该周内日期。切换二级页
    不得改变已选择的日报日期或触发生成。

## 7. AI 与报告规则

- `blocked`：不创建或覆盖 Markdown，不生成 HTML/PNG，不调用在线 AI。
- `ready`：先构建结构化事实和覆盖快照，再执行一次 `review-daily-training` 结构化调用；AI 只解释经过门禁的数据，随后将事实与洞察一次性组装并写入日报。
- `limited`：仅在用户明确选择后生成。缺失维度从 AI 输入和确定性指标中同时移除，正文必须说明
  哪些结论不可得；不能输出综合恢复评分、趋势或负荷风险等依赖缺失数据的结论。**受限版同样执行
  一次 `review-daily-training` 结构化调用**（缺失维度在输入中标记 `status=unavailable` 并随
  `omitted_sections` 传入，模型契约要求保留未知）：用户有训练时，“今天对计划意味着什么”必须包含
  运动概要/当日训练分析，不得因辅助维度缺失整块跳过 AI 导致结论没有任何跑步分析；本地确定性兜底
  同样按 `omitted_sections` 跳过缺失维度结论。
- `TrainingDayFact` 必须先由确定性逻辑落盘并带有唯一 `fact_version`、覆盖状态、结构化
  `evidence` 与 `gaps`；随后生成同来源版本的 `TrainingDayAnalysis`。日报、周复盘和方案草稿读取
  同一版本时不得各自重算事实或训练结构。
- 只有显式日报任务在事实可用后才可调用一次 `review-daily-training`。该调用只生成语义解释；
  `semantic_status=unavailable`、超时、非法结构或容量拒绝都不阻断确定性日报、周复盘或草稿输入，
  失败原因与事实缺口分开显示。周复盘前置流水线不得调用该单日 AI。
- AI 调用失败只影响 AI 洞察，不改变已经通过的数据完整性结论；两类降级原因必须分开显示。
- `athlete_context` 是训练域固化的只读能力背景：AI 只引用其中的确定性字段，不重算、不补造；
  字段缺失或置信度低时相关结论标记未知，不得把 0 值或空字段当作能力数值。
- 重新生成会使用新的覆盖快照替换同日日报，但旧报告若被训练建议引用，仍须保留引用时快照。
- AI 只能使用服务端为报告日期解析并固化的计划上下文。存在生效方案时，执行评价须引用方案 ID、版本、
  生效区间和当日课次；不存在时 `comparison_status=not_applicable`，可以把当日训练作为后续制定方案的
  历史基础，但不能评价为没有执行一份尚未生效的方案。
- 日报把本次 readiness 的 `data_as_of` 作为能力和计划解释的事实截止线。同步晚于该时间完成时，已有日报
  保持历史快照，只提示用户显式重新生成；训练方案的下一次能力计算和周复盘可以使用新事实，但不得反写日报。

## 8. 验收标准

1. 报告日活动覆盖未知时，Web、CLI 和 MCP 都拒绝生成，且没有日报文件或 AI 请求产生。
2. 同步中或同步失败时返回结构化原因和建议动作，不把它们合并成“没有运动”。
3. 报告日已完成活动同步且没有活动时，可以把该日判定为已确认休息。
4. 存在跑步记录但睡眠同步失败时，不会因为活动日历显示已同步而把睡眠视为完整。
5. Provider 不支持的指标不会阻断生成；支持但未授权的指标会显示授权入口。
6. 近 28 天覆盖不足时不计算 ACWR，受限版明确标记该章节不可用。
7. 页面预检为 `ready`、提交前状态变为失败时，服务端拒绝写入并返回最新状态。
8. 受限版必须经过本次显式确认，且列表、详情、图片和机器可读输出都保留不完整标记。
9. 今天的日报包含 `data_as_of` 并显示为暂态；历史日期覆盖完成后显示为最终。
10. 既有旧日报没有覆盖快照时显示“完整性未知”，不得倒推为完整。
11. 从日报页前往同步时，目标报告日期不会丢失；同步页单日日期、日历月份和返回日报链接均指向该日。
12. 当 `D-1` 和 `D` 都有不同活动时，`D` 日报只包含 `D` 的活动；页面、AI 洞察、
    HTML/PNG 和 MCP 均称为“当日训练”或“`D` 日训练”，不得出现把它归到 `D-1` 的“昨日训练”。
13. 旧日报使用历史字段 `yesterday_activities` 时仍可读取，但对用户展示必须按报告日期解释为当日活动；
    新生成日报同时提供规范字段 `daily_activities`，供新调用方迁移。
14. 当方案在 `D+1` 才首次激活时，重新生成 `D` 日报得到 `plan_context.status=no_effective_plan`，且 AI
    洞察中不出现该方案的课次、周目标、完成率或“未执行”结论。
15. 当 `D` 落在某个方案版本的生效区间内时，日报固化该版本及 `D` 日课次；之后激活新版本再查看旧日报，
    原快照不变化，主动重新生成也仍按 `D` 的历史版本解析，而不是读取当前版本。
16. 同步补齐报告日期后，日报页保留 `D` 并重新展示 readiness；只有用户主动重新生成才使用新的数据截止时间。
17. `draft_available`、`scheduled_plan`、`no_effective_plan` 都是不适用的计划执行状态；前两者分别展示草稿
    参考或未来开始日，不能显示成“完全没有方案”。
18. 报告导航名称为“报告”，并在同一入口中区分日报和周复盘；训练调整只在训练页管理；现有日报链接保持可访问。
19. 周报以本地 Natural Week 为范围，必须展示实际活动、数据覆盖、能力与恢复；对应周存在生效方案时才附加计划执行、Progression Decision 和方案版本。它在显式生成前不写入任何训练或报告记录。
20. 周报发现需要调整时，只显示带周 ID 的训练深链；报告页没有确认、激活或自动推进计划的写入路径。
21. 有生效计划的日报固定展示“计划执行与目标进展”区块：当日计划、已记录事实、截至报告日的自然周跑量、
    当前阶段和目标日期；数据无法支持比较时显示原因，不显示完成率或偏离结论。
22. 日报的调整建议只能是说明和训练深链；不得出现日报页确认按钮，也不得把单日表现直接等同为赛事目标达成。
23. 报告入口默认只显示日报二级页；周复盘不与日报生成卡、日报归档同时占据首屏。
24. 日报选择日期后只显示该日的一个状态卡：已生成时提供查看/重新生成，`ready` 时提供生成，`limited` 时提供
    补齐数据和显式受限版，`blocked` 时提供同步入口。完整性明细仅在后三种状态展开。
25. 周中生成或查看周报只显示截至当前事实的“周中检查”，不输出 `advance / hold / deload` 等正式进程决定；
    正式周复盘只能对应已结束自然周。
26. 日报和已完成周复盘列表在记录超过单页容量时必须提供可访问的分页控件；第一页与最后一页禁用越界操作，页面范围提示与列表内容一致，切换页面不会丢失已选择的日期或报告类别。
27. 用户没有 Training Goal、草稿或生效方案时，显式生成已结束自然周仍必须成功；响应中方案关联为空，基础周摘要与数据质量正常返回，且不得以 `active_plan_required` 或 `insufficient_data` 表示“没有方案”。
28. 指定周只有部分日期受训练方案覆盖时，基础复盘覆盖整个自然周，计划执行仅评价方案实际生效的日期，不得把启用前的活动判为未执行或偏离。
29. 无方案正式周复盘不能只展示活动次数、跑量和“结合恢复状态安排下周”等泛化建议；归档卡必须直接展示本周结构与变化结论，并可展开查看最长单次、类型分布、近期对比、恢复/风险和下周动作。
30. 近四周对比只使用活动覆盖完整的自然周并显示样本数；不足一周时标记不可比较，1–2 周时标记样本有限，不得把缺失周按 0 km 参与平均。负荷突增等风险必须给出当前值、参照值与差异依据。
31. 有生效方案的周复盘也只发起一次在线解释请求；从任务进入 `running` 到返回 AI 结果或确定性兜底不得超过 45 秒。超时后任务必须进入终态、释放账户占位，且已有报告、方案和本地复盘事实仍可使用。
32. 同一 `user_id + report_date` 的日报、周复盘和方案草稿读取到相同的
    `fact_version + analysis_version` 时，活动集合、训练结构、质量课判定、覆盖状态、`data_as_of`、
    evidence 和 gaps 逐项一致；仅允许按各自时间范围聚合或省略。
33. 没有历史日报但原始活动覆盖已完成时，系统仍能生成并读取 `TrainingDayFact`；历史日报文件不是周复盘或方案草稿的前置条件。
34. `TrainingDayFact` 的空活动列表只有在活动覆盖为 `complete` 时才可呈现“确认休息”；`unknown`、`syncing`、`failed` 或缺失覆盖不得转成休息、零负荷或未执行。
35. `review-daily-training` 未执行、超时、容量拒绝、返回非法结构或 Provider 不可用时，日报、周复盘和
    方案草稿仍能读取确定性事实、`TrainingDayAnalysis` 与结构化证据，并将语义解释标记为不可用；
    不得把 AI 失败计为事实或周复盘前置流水线失败。
36. 日报只读取日期 `D` 的活动；周复盘只读取用户本地周一至周日的单日事实；方案草稿只读取生成时点以前的所需事实窗口，未来排期不得反向成为事实或历史报告内容。
42. 完整日报的 Front Matter 包含 `athlete_context`：`status=available` 时携带训练域能力画像投影（可持续周跑量、长距离、近期配速、历史能力与中断背景、负荷边界、同步覆盖、置信度）与 `facts_cutoff`；`training_load` 被省略的受限版 `status=unavailable`，正文与 AI 输入均不出现能力/负荷相对结论。
43. 训练域读取失败或没有足够活动事实时，日报不编造能力数值：`athlete_context` 标记不可用或低置信度，AI 洞察对能力相关结论保持未知。
44. 重新生成历史日期日报时，`athlete_context` 按 `capacity_profile(D)` 口径读取（只使用 `D` 及之前事实）；生成后训练域画像变化不反写已有日报快照。
45. CLI、Web、MCP 三条日报入口使用同一 `athlete_context` 构造与门禁，同一 `user_id + report_date` 下投影内容一致。
46. 跑步活动存在分段时，日报展示“整体水平 + 强度分布 + 配速节奏”三块，样本数标注为分段数；无分段时只显示整体水平并说明强度/节奏不可得，不得显示为秒级采样精度。
47. 训练效果缺失且个人阈值（心率或配速）可用时，日报展示估算值并带“估算”标记、估算方法与依据；阈值也不可用时显示“不可得”，不伪造数值。个人阈值只来自档案/平台（用户确认值 → 平台自算 lthr/ltsp → 档案最大/静息心率推导 → 档案 PB 推导阈值配速），不得用近期训练平均心率/配速分位充当；全无时训练内容识别输出“缺少个人阈值心率/配速，强度评估不可用”，不展示“为个人阈值心率的 X%”数字。
48. 配速分位数、前后半程秒差、CV、最快/最慢段全部由分段事实确定性计算并带证据；复合训练（间歇/变速/组合）由分段结构（splitType、work/recovery）识别，AI 不重算。
49. 日报、草稿、周报从同一版本化 `SessionSummaryFacts`（统一 `session-summary` schema）消费；
    草稿/周报在组装事实包时投影压缩概要子集，日报保持全量。重算以 `detail_hash`、schema 与规则版本
    共同判断，历史报告保留生成时引用的 `fact_version`，重新同步/重算只影响新生成或主动重算的事实。
37. 共享单日摘要不增加页面、设置或新的确认步骤；用户仍通过现有日报/周复盘日期控件和训练草稿既有输入完成操作，证据与语义状态使用现有渐进披露区域展示。
38. 同一活动在相同摘要 schema 版本下重复同步或重复读取时，`SessionSummaryFacts` 的量、结构、
    强度和地形结果稳定且不产生重复事实；schema 版本变化后只更新新生成或主动重算的事实，历史报告
    仍保留原引用版本。
39. 只有活动量可用时，报告可以展示 L0 的时长/距离等事实，但必须明确结构、强度或地形不可得；
    L1/L2 结果不得在缺少对应分段或 1Hz 证据时出现。
40. 心率缺失而配速可用时，页面、导出和机器可读输出均显示 `intensity.basis=pace` 及其影响范围；
    不得显示为心率带占比或综合恢复结论。
41. 报告和 AI 输入只包含版本化聚合事实与可定位 evidence，不包含完整 `detail_json` 或 1Hz 数组；
    当摘要维度缺失时，对应报告章节明确标记未知/省略，其他可用章节仍可交付。
57. 日报与周复盘 Tab 在没有任务状态时，Tab 下方不存在可见或占位的状态条，其布局占用高度为 `0`；
    任务进入 `queued` / `running` / 可处理失败时才出现状态信息。
58. 收起任一周复盘归档后，只保留摘要行；正文和所有子分区均退出布局。展开后内容恢复，且展开/收起
    不改变所选周、分页或触发新的生成任务。
59. 日报或周复盘归档为零时，各自只显示一个包含原因与下一步动作的紧凑空状态；列表、分页、空标题、
    空详情分区和无文字背景块不渲染。日报归档列表有数据但某个可选区块无内容时，同样不保留占位高度。
60. 用户显式生成周复盘时，在线周解释开始前已经为范围内每个已发生日期生成或复用
    `TrainingDayFact + TrainingDayAnalysis`，并形成封口的 `WeeklyPrerequisiteManifest`；缺少历史
    日报文件不影响该流程，也不会自动新增日报归档。
61. 同一周在来源事实、schema 和规则均未改变时重复生成，逐日 `fact_version`、`analysis_version` 与
    质量课集合保持一致；只重建变化日期，且整个周任务在线 AI 调用总数不超过 `1`。
62. 当前周的未来日期不会进入前置清单，不会被写成休息或零负荷；已发生日期覆盖未知时保留
    `degraded` 和 gap，周复盘明确说明影响，不把未知日计为休息、漏练或零训练量。
63. 周级在线解释超时、拒绝或返回非法结构时，`WeeklyPrerequisiteManifest`、逐日确定性分析和质量课
    总结仍可归档与查看；不得回退为逐日调用 AI，也不得留下重复任务或长期 `running` 状态。
64. 结构为 `interval`、`tempo`、`fartlek`，或带有效快慢组的 `mixed`，且置信度 `>= 0.60`、
    至少有一个配速/心率主证据时，该活动进入质量课；`aerobic`、`unknown`、恢复跑和休息日不进入。
65. 质量课详情对距离、时长、平均配速、心率、步频、步幅、可靠分段、快慢组和训练效果分别输出值或
    gap。分段数量不可靠时仍可标记强度模式，但不显示分段量或“每公里”结论。
66. 同一标准夹具分别通过 Garmin 和 Coros Adapter 进入统一事实层时，质量课类型、置信门槛、可用指标、
    gaps 与周聚合规则一致；报告/训练消费层不存在 Provider 特判。
67. 本周没有满足证据门槛的质量课时，周复盘显示一行明确结论而非空白卡片；存在证据不足的疑似高强度
    活动时说明未计入原因。一天多节质量课逐条保留，重复同步按活动 ID 去重。
68. 日报、周复盘和方案草稿对同一日期的距离、平均配速、可靠分段、心率、步频、步幅与训练结构读取
    相同 `ValueOrGap` 和 evidence；消费入口省略可用字段时必须记录 `projection_omitted`，不得将其写成
    Provider 缺失。

## 9. 已确认决策

保留“生成受限版”作为明确的次级动作，避免新用户因不足 28 天历史完全无法使用，同时保证任何
缺失维度都不会产生对应结论。完整日报仍是默认和主要动作；受限版必须由用户当次显式确认。

`TrainingDayFact + TrainingDayAnalysis` 是日报、周复盘和方案草稿共享的确定性单日事实与分析；
结构化 `evidence`/`gaps` 是跨入口一致性真相源。显式生成日报时可调用一次
`review-daily-training` 做可选语义解释；周复盘自动补齐逐日前置事实与确定性分析后，只调用一次周级 AI，
不要求手工日报、不自动创建日报归档、不产生 N+1 AI。AI 不可用不阻断事实、质量课总结、确定性周复盘或
草稿输入，且不新增摘要设置、证据编辑器或独立页面。日报、周复盘和草稿分别受单日、自然周和草稿生成
时点事实窗口约束；报告只观察与建议，训练只负责方案确认与生效。
