# 运动摘要提炼上线验收与运营监控

- **适用范围**：Provider 活动明细入库后生成 `SessionSummaryFacts`，并向训练内容识别、共享单日事实、日报、周复盘和 AI 输入提供只读聚合事实的链路。
- **对应设计**：[运动摘要提炼](../design/summary-extraction.md)。
- **运营目标**：在不接触 1Hz 原始明细、不过度承诺 Provider 数据完整性的前提下，让每次消费均能取得版本明确、粒度如实、可回放的运动摘要；低粒度或缺字段必须降级呈现，而非伪造零值或高置信度结论。
- **数据边界**：仅使用服务端落盘的活动来源标识、摘要事实、版本/哈希、质量字段、调用方引用和任务终态。Markdown、页面文案、AI 自然语言、完整 `detail_json` 与 1Hz 数组不作为运营统计事实源，也不得进入运营导出。

## 1. 上线前必须具备的可观测字段

每条生成、复用或失败记录至少可关联以下字段；字段缺失时标记“待补采集”，不以人工抽样替代总体结论。

| 类别 | 最小字段 | 用途 |
| --- | --- | --- |
| 关联与版本 | `user_id`、`activity_id`、`source_provider`、`detail_hash`、`summary_version`、生成时间 | 去重、回放、识别版本升级后的重算 |
| 结果 | `summary_status`（`written`/`reused`/`skipped`/`failed`）、`granularity`（`L0`/`L1`/`L2`）、耗时 ms | 覆盖、性能和降级观察 |
| 质量 | `missing_fields`、`intensity_basis`、可用维度列表、失败/跳过分类 | 区分 Provider 能力、字段漂移与实现故障 |
| 下游引用 | 调用方（analyzer/day-summary/report/week-review/AI）、`activity_id`、`summary_version`、引用终态 | 验证只读复用和版本一致性 |
| 安全边界 | AI 输入摘要大小、是否含原始 `detail_json`/1Hz 的布尔审计结果 | 证明原始明细未越过摘要边界 |

日志或事件不得包含完整 `detail_json`、1Hz 序列、完整 AI prompt/响应、Authorization 或 API Key。`activity_id` 和 `user_id` 只用于受控回放，不进入对外运营材料。

## 2. 指标与统计口径

首个**完整自然周**仅建立基线；没有历史数据时不得编造目标值或以 0%/100% 表示未知。所有分子、分母、排除原因都应能回放到 `user_id + activity_id + detail_hash + summary_version`。

### 2.1 摘要可用覆盖率

```text
摘要可用覆盖率 = 有 written 或 reused、且摘要可读取并版本匹配的合格活动数 /
                 已成功持久化 detail_json 的合格活动数
```

- 合格活动是本统计窗口内成功入库、具备稳定 `activity_id` 与 `detail_hash` 的活动；重复入库同一 hash 只计一次活动。
- `skipped` 仅在上游无可解析活动明细且设计明确允许时单列，不进入“可用”分子；`failed` 单列并保留失败分类。
- 按 Provider、活动类型、摘要版本、L0/L1/L2 分组，防止整体覆盖掩盖单一 Provider 回退。
- 上线阻断：合格活动已入库但摘要不可读、重复入库产生不一致事实，或缺失事实被下游填成零值。

### 2.2 粒度与数据质量分布

```text
粒度占比(Lx) = granularity=Lx 的可读取摘要数 / 可读取摘要总数
心率代理占比 = intensity.basis=pace 的强度摘要数 / 含 intensity 的摘要数
字段缺失率(字段) = missing_fields 含该字段的摘要数 / 可读取摘要总数
```

- L0/L1/L2 是数据可用性标签，不是运动表现评分；L0 或 `basis=pace` 不得自动触发召回、提醒或用户分层。
- 心率不可用而使用配速代理时，必须同时保留 `intensity_basis=pace` 和缺失声明；没有强度维度不应被统计为 `basis=pace`。
- Provider 声明不支持的字段单列为 `unsupported`，不得并入“字段漂移”或“用户未同步”。同一字段在已支持且曾稳定提供的 Provider 上出现连续异常，才作为数据契约观察项升级。

### 2.3 可追溯性与证据完整率

```text
摘要证据完整率 = volume 的每个非空值均能定位到来源字段，且可用结构/强度/地形维度
                 均带有来源、计算策略或代理声明的摘要数 / 可读取摘要数
```

- 缺失维度以 `None` 与 `missing_fields` 表达，属于完整的降级结果；把缺失字段写成 `0`、空字符串或无来源结论属于不完整。
- 证据回放应能说明来源字段或分段/1Hz 聚合策略，不要求在用户界面暴露原始序列。
- 上线阻断：非空数值无法定位来源、`intensity.basis` 与实际使用数据不一致，或摘要版本无法确定。

### 2.4 下游隔离与版本一致率

```text
下游引用一致率 = 使用同一 activity_id 的已完成下游读取中，引用 summary_version、
                 volume 与可用维度均与 activity_summary_facts 一致的读取数 /
                 可回放的已完成下游读取总数
```

- 分调用方观察 `TrainingSessionAnalyzer`、`TrainingDaySummaryBuilder`、日报、周复盘和 AI 输入；未触发的调用方标为 N/A，不算不一致。
- AI 输入审计只验证其来自摘要事实且不含完整 `detail_json`/1Hz 数组；不比较自然语言内容，也不将 AI 失败归为摘要失败。
- 上线阻断：任一调用方自行读取原始明细、引用版本漂移，或低粒度摘要被解释为高粒度证据。

### 2.5 生成耗时（观察指标）

记录单活动从解析开始至事实可序列化的耗时，按 `granularity`、payload 大小区间和 Provider 分位观察。设计给出的本地性能验收为单活动不高于 20ms、90 活动批量不高于 0.5s；运营只记录实际样本与环境，不将合成基准外推为线上 SLO。任何持续回归先保留样本范围、版本和硬件/运行环境，再交由开发定位。

## 3. 上线当天验收清单

1. 用脱敏夹具或受控测试账户各抽样一条 L0、L1、L2（若探针证实当前 Provider 无 1Hz，则 L2 标记 N/A，不以缺样失败）：核对 `granularity`、可用维度、`missing_fields` 与来源可回放。
2. 抽样一条缺心率活动：确认强度存在时 `intensity_basis=pace` 全链路保留；强度不可得时维度为 `None`，不得伪造配速或心率占比。
3. 对同一 `detail_hash` 重复入库：确认事实只复用或确定性重算一次，版本、核心数值与下游读取保持一致。
4. 触发或回放训练内容识别、共享单日事实、日报/周复盘（如适用）及 AI 请求：验证都读取摘要事实，AI 输入审计不含完整原始明细；未触发入口记 N/A。
5. 导出首个完整自然周的五项指标原始分子/分母、按 Provider/粒度的分布、失败分类、排除原因与版本范围；建立基线后再决定是否设置内部告警阈值。
6. 复核性能样本的环境、负载与测量边界。未达设计性能验收、摘要不可读、证据不可追溯、版本漂移或原始明细越界，均不得宣布通过。

## 4. 监控、处置与回滚边界

每日查看覆盖、失败分类、粒度分布、字段缺失和版本漂移；每周按 Provider 回放代表样本。告警只针对可执行问题：摘要写入/读取失败、幂等失效、受支持字段系统性消失、证据不可回放、版本漂移或原始明细进入 AI 输入。

处置顺序：

1. 核对活动入库、`detail_hash`、摘要版本和调用方引用，先区分上游未提供、字段漂移、聚合失败与读取失败；
2. 上游缺字段时保留 L0/L1 降级和质量声明，不手工补值、不把其当作用户未训练；
3. 聚合或版本问题时停止将受影响摘要用于新增高置信度 evidence，保留既有历史报告引用，升级为数据契约/实现问题；
4. 若原始明细越过 AI 边界，立即暂停相关 AI 调用路径，按最小聚合事实降级，并执行脱敏日志核查；
5. 不做自动重跑、群发、召回或数据回填。schema 修复后的版本化重算由开发按设计 ADR 和受影响范围执行，运营只验证重算前后版本与事实边界。

## 5. 验收结论模板

记录统计窗口、Provider 与活动类型范围、合格活动定义、每项指标的分子/分母/排除原因、L0/L1/L2 和 `intensity_basis` 分布、版本范围、抽样回放证据、性能环境、AI 输入边界检查以及未解决风险。无数据、字段未采集或入口未触发时明确记为“无法判定”或“N/A”。
