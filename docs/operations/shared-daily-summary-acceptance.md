# 共享单日摘要运营验收与质量监控

- **适用范围**：同一报告日期的结构化单日摘要，被日报、周复盘和训练方案草稿作为事实输入的场景。
- **目标**：确认事实只由统一构造器定义并生成稳定版本，各入口按同一事实口径复用；AI 摘要不可用时不阻断确定性报告、周复盘或草稿流程。
- **数据边界**：只读取服务端落盘的摘要、证据、报告/草稿引用和任务终态；不新增群发、召回或人工改写事实的流程。
- **口径原则**：首个完整自然周建立基线，不编造行业目标。分子、分母和排除原因必须可回放到 `user_id + report_date + summary_version`。

## 验收前提

1. **共享真相源**：同一输入事实由统一构造器生成稳定的 `summary_version`，各调用方不得维护第二套单日解析。重新同步或事实变化产生新版本时，旧日报仍保留其生成时引用，不静默回写历史报告。
2. **合格日期集合**：报告日期活动覆盖已完成，且绑定 Provider/授权状态可解释；`unknown`、`syncing`、`failed` 和缺失必要覆盖的日期进入“数据不足”，不计入质量率分母。
3. **证据而非文案**：运营统计以摘要中的结构化事实、覆盖状态、`data_as_of`、证据列表和缺口列表为准；Markdown、页面展示和 AI 自然语言不作为事实源。
4. **AI 非阻断**：AI 请求失败、超时、返回非法结构或容量拒绝时，必须保留确定性摘要和可用报告；未执行的 AI 请求不得伪装成成功摘要，也不得阻止用户查看既有结果。

## 四项核心指标

### 1. 摘要覆盖率

```text
摘要覆盖率 = 在合格日期集合中，存在可读取且版本有效的共享单日摘要日期数 /
             合格日期总数
```

同时报以下分项，避免把“有文件”误当成“可供调用方使用”：

- 日报引用覆盖：日报的 `summary_version` 与共享摘要版本一致；
- 周复盘引用覆盖：周复盘涉及的每个已完成日期均能解析到对应摘要版本；
- 草稿引用覆盖：草稿生成所需日期窗口均有摘要或明确的缺口状态；
- 版本过期数、缺失数、解析失败数和因 readiness 排除数。

不设硬性行业阈值。上线阻断条件是合格日期产生摘要后，任一主入口无法读取、引用版本漂移，或缺失被错误填成零值。

### 2. 证据完整率

单日摘要至少应能追溯：报告日期、`data_as_of`、活动/健康覆盖状态、实际活动列表（可为空但需有已覆盖证据）、关键指标来源、分析证据和缺口/省略章节。

```text
证据完整率 = 满足必需证据清单且每条证据可定位到结构化事实的摘要数 /
             已生成共享摘要数
```

“无活动”只有在活动覆盖已完成时才算完整休息日；Provider 不支持的指标记为 `unsupported`，不能按缺失或零值统计。证据缺失按字段计数，至少保留：缺字段数、不可定位证据数、覆盖状态不明数、错误日期锚点数。

### 3. AI 摘要可用性（不阻断）

分别统计 AI 路径和最终用户可用路径，不把 AI 失败计为报告失败：

```text
AI 摘要可用率 = 返回合法结构化 AI 摘要的请求数 / 实际发起的 AI 请求数
最终摘要可用率 = 生成确定性摘要或合法 AI 摘要的日期数 /
                 通过 readiness 且触发生成的日期数
```

按 `ai_validated`、`ai_repaired`、`deterministic_fallback`、超时、非法结构、Provider 错误和容量拒绝分组。必须另报“AI 不可用但主流程成功”的日期数；该数不应进入报告失败分子。只有 readiness 阻断、写入失败或共享摘要不可读才算最终摘要不可用。

### 4. 跨日报 / 周报 / 草稿一致性

对同一 `user_id + report_date`，比较三个调用方读取到的结构化字段，而非比较自然语言：活动集合及距离/时长、恢复指标、数据覆盖状态、`data_as_of`、摘要版本和缺口列表。

```text
跨入口一致率 = 三个已实际读取摘要的入口，其字段与共享摘要逐项一致的日期数 /
              至少被两个入口读取且属于合格集合的日期数
```

入口未触发不算不一致；只存在日报或周报的日期进入“未覆盖入口”分项。任何入口出现日期偏移（例如把 D 标为 D-1）、版本漂移、活动集合不同、把缺口补成零值，均记为一致性事故并保留请求/摘要版本证据。

## 上线当天清单

- 抽样 3 个有活动日、1 个已覆盖休息日、1 个 `limited` 日：核对摘要版本、`data_as_of`、覆盖状态和证据链接。
- 对同一日期分别打开日报、已完成周报和草稿预览，确认三者展示的结构化事实相同；没有实际引用的入口标为 N/A，不强行补样本。
- 模拟 AI 超时/非法响应/容量拒绝：确定性摘要仍可查看，页面明确标注降级原因，且不产生错误的“AI 成功”记录。
- 导出首个完整自然周的四项指标原始分子、分母、排除原因、版本漂移数和失败分类；建立基线后再决定阈值。
- 检查日志和埋点不包含 API Key、Authorization、完整 Prompt、完整用户事实或上游响应正文。

## 监控与异常处理

每日检查摘要覆盖、证据缺口和降级分类；每周按报告日期回放跨入口一致性。告警只触发可执行问题：摘要不可读、版本漂移、证据字段系统性缺失、确定性 fallback 也失败。AI 单独失败但最终摘要可用时记录观察项，不暂停报告链路。

处理顺序固定为：

1. 先确认共享摘要是否写入、版本是否唯一、调用方是否发出读取请求；
2. 若为同步覆盖不足，等待或补齐同步后由用户显式重新生成；
3. 若为 AI 失败，保留确定性结果并观察恢复；
4. 若为跨入口不一致、错误日期或错误生效版本，暂停宣布通过，保留现有报告/草稿状态，升级为数据契约或实现问题。

## 验收结论模板

记录统计窗口、合格日期定义、四项指标分子/分母、排除数、共享摘要版本范围、AI 降级分类、抽样日期及未解决风险。没有证据时使用“未采集/无法判定”，不得用 0% 或 100% 代替。
