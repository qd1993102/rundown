# 草稿生成前补充信息窗口

- **日期**: 2026-08-10
- **类型**: feature

## 背景与动机

用户在生成训练草稿前可能有一些只影响近期安排的变化，例如短期出差、睡眠不足、训练偏好或目标侧重点。已有目标、可训练日、单次最长时间和同步事实不应被新的复杂问卷替代，因此需要一个单字段、可跳过的输入窗口。

## 方案选择

- 在现有向导的基础与现实约束之间展示一次轻量窗口，不增加新页面或第四个正式步骤。
- 使用 `additional_context`，最多 280 个 Unicode 字符；用户明确选择“提交并继续”或“跳过并继续”。
- 仅把内容注入同一次 `draft-training-scheme` 请求的 `user_supplement` 区块，并标记为未验证自述；不覆盖确定性事实、目标和安全底线。
- 草稿只保留 `request_id`、字符数、状态、是否采用等元数据，不把原文写入 Training Goal、Training Scheme、报告或训练记忆。
- 空值、超长截断或补充信息不可用时，走无补充信息路径，不增加第二次 AI 调用，也不阻断核心草稿流程。

## 实现步骤

1. 更新训练产品真相源，明确窗口位置、字段、隐私边界和降级规则。
2. 更新训练系统设计与 `draft-training-scheme` Prompt，约束用户自述只作为补充上下文。
3. 在训练向导加入窗口和提交/跳过动作；请求携带 `additional_context` 与 `request_id`。
4. 在草稿事实包中临时传递补充上下文，草稿结果只保存脱敏元数据。
5. 增加事实包、Prompt、Web 页面和异步草稿链路回归测试。

## 遇到的问题与解决

- 既有草稿接口只定义训练日和单次时长：保留这两个核心准入字段，同时将补充文本定义为可选的本次请求上下文，而不是新的长期设置。
- 异步任务需要保留请求快照：原文只由后台任务闭包短期持有，终态后不写入方案；读模型只展示是否采用和字符数，避免泄露用户自述。
- 用户补充内容可能与同步事实冲突：Prompt 明确要求将其视为未验证自述，不能覆盖确定性事实或安全底线。
