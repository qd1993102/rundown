# 训练内容识别 v1

- **日期**: 2026-07-31
- **类型**: feature / architecture

## 背景与动机

训练日报缺少一层稳定的训练内容理解：历史上下文依赖用户是否生成日报，间歇结构没有进入分类，累计爬升也没有成为坡跑或山地专项证据。第三方标签无法单独解决，因为同一绝对配速对不同能力的运动者可能代表不同刺激。

## 方案选择

采用确定性、可解释的双轴领域模型：训练主类型表达有氧、节奏、间歇或未知，地形属性表达平路、坡地、越野、山地或未知。两者组合展示，但分别保存证据。

没有引入 LangChain，也没有把分类写进 AI prompt。AI 只消费结构化结果。Provider 原始活动和训练负荷保持事实层，派生分析使用独立版本表，避免算法升级覆盖历史解释。

第一版选择命名的 `AnalyzerPolicy` 规则而非黑盒模型，便于用历史标注样本回放和调整。当前默认阈值已通过边界测试，但真实多平台校准仍是发布前验收项。

## 实现步骤

1. 为训练类型、地形、个人基线、数据质量和分析版本建立产品与技术合同。
2. 先添加有氧、节奏、间歇、坡地、越野、山地、复合标签和历史日报缺失的复现测试。
3. 实现活动事实归一化、活动发生前 28–42 天个人基线和双轴分类规则。
4. 新增不可变 `activity_analyses` 与独立 override 表，按输入指纹幂等保存。
5. 同步持久化爬升等活动事实，补齐常见 Provider laps/splits，并修复重复分段。
6. 日报、AI 教练历史工具和 MCP 改用 SQLite 原始活动及结构化分析。
7. 修正 7/28 天 ACWR、负荷字段名和 HRV 状态大小写，运行全量测试。

## 遇到的问题与解决

- 有氧、节奏、间歇属于训练结构/刺激，越野属于地形，强行四选一会丢失“坡地间歇跑”等复合语义，因此拆成双轴。
- 累计爬升可以证明坡地负荷，但不能单独证明路线为越野；`trail` 需要 Provider、名称或用户确认等额外路线证据。
- 只有多个工作段但没有恢复结构不能判为间歇，v1 要求至少两组工作段且存在对应恢复段。
- 当前能力会影响强度解释，但不能反向改变已经发生的分段和地形；恢复状态只进入训练影响与后续约束。
- 旧活动表没有统一扩展列，通过幂等 `ALTER TABLE` 迁移；缺失爬升改为 `null`，不再伪装成零爬升。
